# CourseCore 产品需求文档

> 文档状态：当前产品基线
>
> 更新时间：2026-08-07
>
> 本文区分“当前已实现”“部分实现”和“目标设计”。课程资料、PDF、题库 Markdown 和数据库实践文档不等于已经接入产品的课程或功能。

## 1. 产品定位

CourseCore 是面向大学生的基础课程学习和刷题平台，核心闭环是：

```text
学习课程 → 完成练习 → 获得判分反馈 → 进入错题/复习 → 查看学习记录
```

当前产品重点是高等数学与大学物理的课程内容、题目练习和期末试卷；线性代数、概率统计等属于产品方向和资料储备，不能在当前版本中标记为已上线完整课程。

## 2. 目标用户与价值

- 大学生：需要课程讲义、题目训练和期末复习入口。
- 自主学习者：需要可直接访问的课程小节、公式渲染和本地进度。
- 已登录用户：需要云端进度、答题记录、错题本、复习和排行榜。
- 内容管理员：需要维护课程、题目、试卷、理论内容、知识点和用户内容。

产品价值：让课程资料、练习反馈和复习记录在一个连续的学习流程中可用，而不是只提供静态题库。

## 4. 功能状态

### 4.1 学习与课程

- 课程、模块、小节树：已实现。
- 理论 Markdown 与 MathJax 公式：已实现，内容来源分为构建数据和运行时内容。
- 小节完成状态与本地进度：已实现。
- 登录后的云端进度同步：已实现基础链路，仍保留 fallback。
- 课程访问控制：已实现，规则位于 `src/config/access.js`。

### 4.2 刷题与判分

- 单选、多选、判断、填空、计算、证明/解答等题型：已实现不同渲染和校验路径。
- 通用 `quizSession`：已实现，支持试卷/题型练习、题号导航、提交报告和部分会话恢复。
- 服务端判分：已实现基础链路，需要登录并通过 BFF。
- 错题本与复习间隔：已实现基础状态机和复习页面。
- 代码题隔离执行：属于预留能力，不应在当前版本标记为完整产品功能。

### 4.3 知识库与社区

- 错题库、复习队列、掌握度统计：已实现基础能力。
- 收藏：已有入口和部分页面能力，内容类型覆盖需要继续核对。
- 社区文章、发帖、审核和收藏：已实现基础能力；部分读写仍直连 Supabase。
- 以知识点驱动的完整学习路径、遗忘曲线策略和相似题推荐：目标能力，不能全部视为已实现。

### 4.4 用户与后台

- 登录、登出、会话恢复：已实现。
- 注册、重置密码入口：当前 UI 暂时关闭，不标记为可用。
- 用户资料、头像、学习记录：已实现基础能力。
- 管理员内容编辑、题目、试卷、知识点管理：已实现基础后台，权限和 BFF 化仍需继续收敛。

## 5. 产品原则

1. 练习反馈必须回到学习闭环：判分、解析、错题和复习不能割裂。
2. 游客可以完成基础浏览和本地学习；云同步和个性化能力需要登录。
3. 答案揭示要与练习场景一致：即时练习、提交后查看和复习会话不能混用同一规则。
4. 内容源、构建产物和运行时数据必须可区分，不能让用户或开发者直接编辑生成文件作为长期方案。
5. 产品文档中的“已完成”必须能在对应路由、服务或数据中找到证据。

## 6. 核心用户流程

### 游客学习

```text
首页 → 课程 → 小节 → 理论/练习 → localStorage 保存进度
```

### 登录用户刷题

```text
首页/刷题中心 → 试卷或题型 → quizSession
→ 提交答案 → BFF 判分 → 答题记录/错题本 → 复习
```

### 内容管理员

```text
管理员登录 → /admin → 课程/题目/理论/试卷/知识点编辑
→ Supabase 持久化 → 构建或运行时内容更新
```

管理后台当前尚未完全通过 BFF，因此“服务端统一业务权威”仍是架构目标，不是完整的当前产品事实。

## 7. 关键数据概念

### 7.1 课程

```js
{
  id: 'calculus-1',
  title: '高等数学（上）',
  modules: [
    {
      id: '...',
      title: '...',
      items: [
        { id: '...', title: '...', type: 'theory' },
        { id: '...', title: '...', type: 'quiz' },
        { id: '...', title: '...', type: 'training' },
      ],
    },
  ],
}
```

### 7.2 题目

题目由 `questionType` 和 `src/config/question-types.js` 的映射决定行为。常用字段包括：

```js
{
  id,
  itemId,
  courseId,
  questionType,
  title,
  content,
  options,
  answer,
  answers,
  blanks,
  tolerance,
  unit,
  solution,
  image,
  difficulty,
  tags,
  source,
}
```

### 7.3 用户学习数据

主要概念包括 `profiles`、`answers`、`progress`、`wrong_book`、`practice_records`、`favorites`、`my_papers` 和社区文章相关表。用户数据必须按用户身份隔离；具体权限以 Supabase schema、RLS 和 BFF 实现为准。

## 8. 非功能要求

- 前端构建可复现，Markdown/数据源与 `src/data` 生成物关系明确。
- 数学公式和题目内容在桌面与移动端可读。
- 用户接口需要 JWT 鉴权；服务端密钥不能进入浏览器。
- 内容接口默认不返回答案和解析；答案通过判分/reveal 业务接口按规则返回。
- 重要页面支持深链访问，预渲染和 SPA fallback 行为一致。
- 断网或 BFF 暂时不可用时，静态课程和本地进度仍尽可能可用。

## 9. 当前验收基线

以下事项作为当前版本的验收基线：

- 游客可以访问首页、课程、小节和部分练习。
- 登录用户可以进入刷题会话并提交支持的题型。
- 服务端判分接口能返回判定结果，并更新答题记录/错题本。
- 错题复习和用户记录页面能读取已有数据。
- 管理员可以进入后台完成已支持的内容管理操作。
- `/api/v1/healthz` 正常，未登录用户访问受保护 BFF 路由得到 401。
- 生产构建使用 Cloudflare Pages + Pages Function 的部署结构。

## 10. 明确不在当前基线的内容

- “无需后端即可完整运行”不是当前准确描述。
- 线性代数、概率统计不是当前已验收的完整课程。
- 注册和重置密码不是当前可用入口。
- 所有业务已经 BFF 化不是当前事实。
- 所有答案都已从静态 bundle 移除不是当前事实。
- 遗忘曲线、知识点推荐、AI 推荐和完整社区治理属于后续产品目标，需单独立项验收。
